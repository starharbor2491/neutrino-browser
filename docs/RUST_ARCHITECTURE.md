# Rust interface and core boundary

The browser interface is rendered by `crates/neutrino-shell`. Rust owns the HTML, control state, command search, seven-step setup, tab move validation/undo, editor drafts, docking, appearance choices, and navigation between screens. The bundled CSS supplies the visual system; a small JavaScript adapter handles DOM events, drag/drop, focus, editable-node reconciliation, and geometry reporting. No remote web content is used to render the interface.

A private, nonpersistent WKWebView displays these bundled assets through `neutrino-ui://shell`. Its message handler accepts only its own main frame. Website engine views are separate native children placed in the rectangles reported by the shell. Opening a modal hides those website views, and generation checks reject stale geometry. A crashed shell reloads the bundled document without discarding the Rust interaction state.

The C ABI exchanges bounded JSON and opaque handles. Rust owns and frees its returned strings. The native host validates IDs against the current Profile/Space and only permits declared commands. Password values remain in Keychain and never enter the browser snapshot. Auxiliary download windows receive only their download capability.

Rust also owns session normalization/tree/split/archive policy, Space/profile normalization and removal/restore, live-tab ownership mutations, setup CRUD and Space association, scoped/newest-first note metadata indexing, organization application, Chromium-to-WebKit library conversion, module filesystem inventory/payload integrity/provider selection/dependency planning/settings/catalogs/journal recovery, safe bounded imports, release/engine/catalog/update-channel selection, identity claim validation, resource-frame bounds, address/search resolution, AI endpoint validation/canonicalization, organization proposal validation, reader-feed parsing, blocking rules, bookmark HTML import/export, SQLite transactions/revision ordering/checkpoints, and SVG icon rasterization. The database schema and external data directory remain compatible with the updater. Bookmark export failures propagate rather than producing empty files.

Swift remains in the AppKit/WebKit/CEF view adapters, application lifecycle, Keychain, native file/default-browser/permission dialogs, downloads, account networking, and signed distribution services. Swift Codable models are DTO/ABI adapters. Native workers are separate Rust executables. App replacement retains Foundation copy/rename and macOS code-seal callbacks because copying signed framework bundles must preserve native bundle metadata. Account HTTP transport uses URLSession and macOS trust; claims/endpoint policy are Rust. Some adapter orchestration and approval-difference checks still live in Swift and remain migration work; this is not a claim that every portable decision has been removed. The rendering and interaction code no longer relies on the previous SwiftUI screen collection. CEF integration remains Objective-C++ against upstream CEF, with ABI 7 custom browser chrome and ordinary-tab close requests.

## Build

Rust 1.88 or newer, Swift 6/Xcode, Python 3, SQLite headers, and CMake are required. `scripts/build-rust.sh` builds the static library before SwiftPM links it. `scripts/test.sh` runs the Rust and Swift suites plus packaging/acceptance regressions. `Cargo.lock` pins dependencies. macOS packaging compiles the supplied `neutrino.svg` to an icon set without changing its artwork.

`cargo run -p neutrino-shell --bin preview` provides a loopback fixture harness at `127.0.0.1:4317`; `/setup` opens first run. It is not bundled and does not contain a website engine, Keychain, or live Profiles. It verifies renderer interactions only. Native tests and installed-app acceptance are separate gates.

## Language statistics

GitHub counts test and launch-acceptance sources in the language graph. Swift's historical majority included the previous SwiftUI screen collection, portable library policy, macOS framework adapters, and that test code. Rust now owns the rendered interface and the shared policy services listed above. Python is exclusively repository automation; neither Python nor the loopback fixture server is packaged. Source-byte ratios are not used as an acceptance gate, and working tests/build tooling are not deleted to alter the graph.

JSON uses serde_json's correctly rounded floating-point parsing so Swift Date values retain their exact binary representation across normalization/storage. The shell ABI accepts 8 MiB; note list projections contain metadata only, with the full body and quotation restricted to the selected note.
